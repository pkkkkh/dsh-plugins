# dsh-handoff

[![CI](https://github.com/zhenbang1216/dsh-handoff/actions/workflows/ci.yml/badge.svg)](https://github.com/zhenbang1216/dsh-handoff/actions/workflows/ci.yml)

把 DeepSeek Harness 的一个会话，变成一份**可以交给下一个会话的交接文档**。

上下文快用完、任务还没做完，或者你要离开一段时间再回来——`dsh-handoff` 会读一遍当前会话，生成一份 markdown：先是一段能单独读的**接手摘要**，然后是任务与目标、已确认的决定、当前状态与证据、下一步、未完成与风险、踩过的坑、关键文件与命令，最后附一段可以直接粘贴给下一个会话的开场白。

- **`/handoff` 命令**：随时手动生成，可以带一个关注点（`/handoff 重点写测试`）。
- **`handoff` 工具**：模型自己也能调用——上下文将满时，它可以主动把现状写下来。
- **侧边栏「交接文档」页**：列出历史文档（版本 / 搜索 / 相对时间）、渲染预览、复制与下载，并能为任意活动会话一键生成。
- **「接续到会话」**：在面板里选一份文档、选一个活动会话，直接把它注入对方的上下文（不产生用户消息，也不开新的一轮）。
- 文档落到会话工作目录的 `.dsh/handoff/`，同时维护一份 `latest.md`，下一个会话直接读它就行。

## 安装

```sh
# 从本仓库源码安装（目录即插件；lib/ 是随仓库提交的构建产物，clone 即可用）
git clone https://github.com/zhenbang1216/dsh-handoff.git
dsh plugin --profile desktop add file:$PWD/dsh-handoff

# 发布到 npm 之后
dsh plugin --profile desktop add dsh-handoff
```

安装会把包加进该 profile 的 `dsh.profile.bundles`，重启 Harness（或在该 profile 的插件页禁用再启用）后生效。

如果 `dsh plugin` 因为 profile 的 pnpm store 路径不一致而失败（换过盘符或 Node 版本时常见），可以直接手工装：把仓库目录以 junction/软链接放到 `<profile>/node_modules/dsh-handoff`，再把包名加进 `package.json` 的 `dsh.profile.bundles`。本机的 `desktop` profile 就是这么装的。

## 使用

在输入框输入：

```text
/handoff
/handoff 重点说明数据库迁移为什么停在第三步
```

或者直接跟模型说「生成交接文档」，它会调用 `handoff` 工具。工具也可以带关注点：

```text
先别改代码，调用 handoff 工具，把测试那部分写详细一点。
```

生成后，会话记录里不会多出任何模型消息——这是一次辅助调用，不是一轮对话。

长任务可以隔一段时间再生成一次：新版本会自动参考上一份，保留仍然成立的事实和决定，只更新变化的部分。旧文档不会被删除，`previous` 把它们串成一条链。

### 新会话接续

在**新会话**里把上一份文档读进上下文：

```text
/handoff resume                 # 注入 latest.md
/handoff resume handoff-20261025-214005-重构登录模块.md
```

它会以「上一个会话留下的交接文档」的身份注入一条模型可见的上下文（不是用户消息，也不开新的一轮），并附上一段对齐要求：以文档为既有上下文、从接手摘要与下一步开始、已定的事不再重议、与工作区冲突时以工作区为准。超过 30000 字符时截断并说明。注入来源标记为 `dsh-handoff`，便于追溯。

也可以在侧边栏「交接文档」页里点文档头部的 **接续到会话**：确认层会列出当前进程里活着的会话（默认选中消息数最多的那个），确认后同样以 `dsh-handoff` 身份注入，成功后顶部提示「✅ 已接续《文件名》（N 字）」。目标会话必须已经有活动实例；没有的话先给它发一条消息激活。

## 产出

```text
<工作目录>/.dsh/handoff/
├─ handoff-20261025-214005-重构登录模块.md   # v1，每次生成一份，按时间排序
├─ handoff-20261026-085833-补测试.md         # v2，头部记着 previous 指向 v1
└─ latest.md                                 # 指针：写明最新是哪一份，不是副本
```

文档结构（由提示词约束，模型逐节填写）：

| 小节 | 回答的问题 |
|---|---|
| 接手摘要 | 在做什么、现在到哪、下一个动作、绝对不能做什么——**只读这一段也能接着干** |
| 任务与目标 | 最初要什么、验收标准是什么、后来追加或推翻了什么 |
| 已确认的决定 | 选了什么、为什么、否掉了哪条路 |
| 当前状态 | 已完成 / 进行中 / 未开始，每条带证据（文件、命令输出、测试名） |
| 下一步 | 按顺序、可执行、带验证方式，第一步要小 |
| 未完成与风险 | 阻塞项、待用户拍板的问题、未验证的假设 |
| 踩过的坑 | 走过的弯路，别再走一遍 |
| 关键文件、命令与环境 | 接手的人该先看哪几个文件、跑哪几条命令、环境是什么 |
| 给下一个会话的开场白 | 可直接粘贴的一段话 |

顺序是有意的：注入到新会话时超过 30000 字符会截断，摘要放在最前面，即使只剩前半部分也仍然能用。

写第二份（v2）时，生成器会把上一份的正文（限 8000 字符）一并交给撰写模型，并要求「保留仍成立的事实、更新状态、删掉已被推翻的结论」，所以反复生成不会退化成两份互相矛盾的文档。

### 版本与时间

每份文档的头信息（YAML front matter）和标题下那一行都会写明版本与新鲜度：

```yaml
created: "2026-10-26T08:58:33+08:00"      # 生成时间
updated: "2026-10-26T08:58:33+08:00"      # 最后写入时间（人工改过就跟着变）
version: 2                                  # 同一个输出目录里的第几份，从 1 开始
session-activity: "2026-10-26T08:57:12+08:00"  # 这份文档反映的对话最后活动时间
previous: "handoff-20261026-085801-….md"   # 上一份，形成链条
generator: dsh-handoff@0.4.0
```

```markdown
> v2 · 生成于 2026-10-26 08:58:33 +08:00 · 会话最后活动 2026-10-26 08:57:12 +08:00 · 上一份 `handoff-20261026-085801-….md`
```

`latest.md` 是一行指针而不是副本：

```markdown
---
kind: latest-pointer
latest: "handoff-20261026-085833-补测试.md"
version: 2
updated: "2026-10-26T08:58:33+08:00"
---
```

所以「哪份最新」有两个等价答案：看 `latest.md` 指向谁，或按文件名里的时间戳取最大。侧边栏列表里最新那份还带一个 **最新** 徽标。`/handoff resume` 会自动跟随指针；旧版本留下的「副本式 latest.md」也能正确识别。

## 界面

侧边栏里有一行 **交接文档**，点开就是整页：

- **顶部**：选会话（记住上次选的那个），填一个关注点；回车或点「生成交接文档」直接生成，生成完自动打开新文档。
- **左栏**：该会话目录下的历史文档，按时间倒序。每行给出标题、`vN` 版本徽标、**最新** 徽标、相对时间、大小与关注点；支持搜索（标题 / 版本 / 文件名 / 关注点）、刷新，以及 `↑` `↓` `Home` `End` 移动、`Enter` 打开。
- **右栏**：文档正文按 markdown 渲染——标题层级、列表、任务项、代码块（块内可复制）、表格、引用、链接、行内代码；顶部固定显示版本、模型、生成时间、消息数、关注点、上一份与生成器。
- 「给下一个会话的开场白」一节会被识别出来，收进一张高亮卡片，并带一个 **复制** 按钮——这是最常被粘贴走的部分。
- 「原文」切换到原始 markdown，「复制全文」与「下载 .md」不离开页面就能取走文档。
- 加载、空列表、无选中、读取失败各有明确文案与重试入口；生成中按钮显示进度，成功/失败用一条可关闭的提示条说明原因（带宿主返回的错误码）。
- 宽度小于 920px 时自动改成上下布局，列表限高、正文在下。

配色、圆角与字号都读宿主的 `--dsw-*` design tokens（label / bg-layer / border / interactive / markdown 等），因此跟随明暗主题、字号设置和第三方主题；缺少某个 token 的旧构建会退回中性兜底值，不会变成裸样式。面板只带一份 scoped 样式表（`.dh-*`），随面板卸载移除，不改宿主全局样式。

页面通过插件自己的 HTTP 接口拿数据（`/api/dsh-handoff/*`），走浏览器同源 Cookie，和其它 Host 请求一样受鉴权保护。`/docs` 除了文件名、大小、时间，还会解析每份文档的 front matter，返回标题、版本、模型与关注点，列表因此不必先读正文。`/attach` 负责接续：校验目标会话存活、按裸文件名读取该会话目录下的文档、解析 `ctx.agents.get(sessionId)`，再通过 `agent.inject` 把 `frameForInjection` 的文本注入进去。

插件页的 `dsh-handoff` 卡片把配置按「输出 / 模型 / 记录 / 写作」分组，逐项给出中文说明和这次运行实际加载的值。

## 设置

在「插件」页的 `dsh-handoff` 配置卡片里查看当前生效值；修改写进 profile 的 `cordis.patch.yml`，重新加载插件后生效：

| 选项 | 默认 | 说明 |
|---|---|---|
| `outputDir` | `.dsh/handoff` | 输出目录，相对会话工作目录；绝对路径也可 |
| `filenamePrefix` | `handoff` | 文件名前缀 |
| `writeLatest` | `true` | 同时写 `latest.md` |
| `provider` / `model` | 空 | 两者都填才生效；留空沿用会话当前模型 |
| `maxInputChars` | `48000` | 会话记录字符预算，超出时保留头尾、省略中段 |
| `maxOutputTokens` | `4096` | 生成文档的输出上限 |
| `includeToolResults` | `true` | 把工具结果写进记录（逐条截断） |
| `includeReasoning` | `false` | 把模型思考过程写进记录 |
| `language` | `auto` | `auto` 跟随对话语言，或固定 `zh` / `en` |
| `extraInstructions` | 空 | 追加给撰写器的额外要求 |
| `autoGenerate` | `true` | 自动在边界上生成交接文档（见下节）；关掉就只剩手动 `handoff` / `/handoff` |
| `autoEveryTurns` | `5` | 每完成多少个回合补一份自动文档 |
| `autoMinMinutes` | `30` | 同一会话两份自动文档之间的最小间隔（分钟） |

## 自动生成

手动工具的问题是没人点时它就不跑：长会话一路跑下去，下一个会话读到的还是几小时前的旧文档。插件因此挂了两个自然边界：

- **`compaction/start`**——上下文要压缩了，说明已经满了：压缩前先写一份，摘要才有现成依据。
- **`turn/end`**——每完成 `autoEveryTurns` 个回合补一份心跳；`autoMinMinutes` 兜住频率，别把长会话刷成流水账。

行为约定：每会话**一次只跑一份**（in-flight 去重）；子代理会话（`header.origin === 'subagent'`）跳过，父会话负责交接；生成失败只往 `<outputDir>/auto.log` 写一行，**绝不影响会话本身**；成功后照常维护 `latest.md`。

## 设计要点

- **不碰对话**：只做一次辅助模型调用（`ctx.llm.stream`），不写会话历史，不占上下文；只有结构缺小节时才再补一次。
- **写给「零上下文」的读者**：提示词把读者设定为完全没有这段对话的会话，要求保留用户原话里的硬性要求、记录「最新要求推翻了什么」、把决定连理由一起写。
- **摘要前置**：文档第一小节是「接手摘要」，单独可用；`/handoff resume` 注入超过 30000 字符会截断，先读到的一定是最关键的部分。
- **工具活动清单**：从全部消息里统计改过/读过哪些文件、跑过哪些命令、哪些调用失败过，作为「关键文件、命令与环境」的权威清单——即使记录被截断，路径和命令也不会丢。
- **沿用上一份**：目录里已有文档时，把上一份（限 8000 字符）交给撰写模型，要求保留仍成立的事实、更新状态、删掉被推翻的结论。
- **结构自检**：生成后逐节核对 9 个标题；缺了就补一次完整重写，避免拿到一份没有摘要的半成品。
- **路由跟随会话**：默认用会话里最后一条助手消息实际使用的 provider/model，所以你用哪个模型，交接文档就是哪个模型写的。
- **预算内截断**：会话很长时按字符预算保留开头（任务）和结尾（最新进展），中间用显式标记说明省略了多少条——模型知道记录不完整，不会假装看过。
- **失败可解释**：provider 报错会带着原始 failure code 冒出来（如 `RATE_LIMIT`），不会悄悄生成半份文档。
- **只写事实**：提示词禁止编造，不确定的地方要求写「待确认」。

## 排查

先跑一次安装自检，它会逐项确认 profile 里的依赖、bundle 列表、两个产物和客户端包形态：

```sh
node scripts/check-install.mjs desktop        # 或 pnpm check:install
```

- **侧边栏没有「交接文档」**：先确认插件在「插件」页里是启用状态；禁用再启用一次会重新挂载浏览器半身。宿主侧加载失败会在同一页显示错误条目。
- **面板还是旧样子**：浏览器半身在页面加载时取包，刷新一次即可看到新界面；宿主半身的改动（`/docs` 多返回的标题/版本等字段）要重载插件或重启 Harness 才生效——不重载也能用，只是列表少了版本与标题，UI 会退回文件名。
- **面板能打开但显示「会话列表读取失败: HTTP 404」**：宿主的 exact 路由没注册上。原因是 Connection 的服务契约随版本变过——0.2.1 线要用 `connection.registerFetchRoute(owner, route)`（旧线是 `connection.fetch.register(route)`），且 `route.path` 必须落在 `/api/<...>` 通道里、每段只允许 `[A-Za-z0-9_$.-]`，否则注册时直接被拒。本插件两者都兼容；出现 404 说明宿主加载的是旧构建，重新加载插件或重启即可。
- **命令 `/handoff` 没出现**：命令由 Web 客户端提供；无 UI 的 headless 运行里只有 `handoff` 工具。
- **生成失败并带错误码**：`NO_ROUTE` 表示会话还没有模型回复、且没有配置 `provider`/`model`；`RATE_LIMIT`、`AUTH` 等是模型服务商原样返回的失败码。
- **找不到历史文档**：列表只看当前会话工作目录下的 `outputDir`；换会话或改过 `outputDir` 后看到的是另一个目录。

## 开发

```sh
pnpm install
pnpm typecheck
pnpm test
pnpm build        # 产物：lib/index.js（宿主）+ lib/client.js（浏览器）
pnpm integration  # 在真实 Cordis 里挂真 SessionStore/CommandRuntime，跑一遍 /handoff
```

`pnpm integration` 用 0.2.1-rc.3 的真实服务跑一遍插件：注册工具、发现命令、执行 `/handoff`、写出文档，并断言会话日志里只有 `command/run` + `command/done`、没有开 turn。模型调用由脚本内的假 provider 提供——账号路由只有桌面宿主能授权。

仓库结构：

```text
src/
├─ index.ts       # 插件入口：注册工具与 /handoff 命令
├─ config.ts      # schemastery 配置（自动生成设置表单）
├─ generate.ts    # 路由解析 → 提示词 → 流式调用 → 缺节补写 → 落盘
├─ transcript.ts  # 会话消息 → 带轮次与工具参数的记录；工具活动清单
├─ prompt.ts      # 系统提示词、9 节契约、缺节检测（中/英）
├─ markdown.ts    # front matter 写入与解析、正文清洗、文件名
├─ store.ts       # 目录解析、文件读写、列表摘要
├─ errors.ts      # 稳定错误码
└─ client/
   ├─ index.ts    # 浏览器入口：注册侧边栏页、侧边栏行与配置卡片
   ├─ page.ts     # 整页：会话/列表/搜索/生成/预览/空态与错误态
   ├─ card.ts     # 插件页上的配置卡片（分组展示生效值）
   ├─ markdown.ts # 文档体 → 块/行内节点（只渲染 React 元素，不碰 innerHTML）
   ├─ api.ts      # 路由调用、错误码 → 人话
   ├─ format.ts   # 相对时间、大小、复制、下载、标题回退
   ├─ styles.ts   # scoped 样式表（消费宿主 --dsw-* token）
   └─ ui.ts       # 16px 网格的内联图标
```
